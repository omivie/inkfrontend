## 3. Item 61.3: what the printer-page H1 and title read

- **H1:** your prerender's `<h1>`, mirrored as is ("Brother HL-L2375DW Toner NZ"). Until it arrives, or if it fails, the H1 shows the printer's **`display_name`** (`PrinterName.of`: `display_name`, else `full_name`, else brand + `model_name`).
- **`<title>`:** your prerender's `<title>`, mirrored as is. The fallback, used only when your prerender cannot be reached, is `"<display_name> <Toner|Ink> Cartridges | InkCartridges.co.nz"`, or `"<display_name> Cartridges | …"` when the page lists more than one kind. Before this deploy, the first paint briefly read "Compatible Ink for <slug> NZ"; it now reads `display_name`.

## 4. Asks

1. **`compatibility_promise` in `GET /api/site/trust`.** The printer endpoint carries no `trust_signals`, and a first-time visitor never reads `GET /api/cart` (your 28 Sep ask). So the printer page reads the label from the first listed product's `GET /api/products/:sku`, which costs one extra edge-cached request. With it in `/api/site/trust` (already loaded on every page for `warranty`), that request goes away. The FE already checks site trust first, so this needs no FE change when you ship it.
